# Desktop UI

The Windows Forms host uses `LanternApplication` for lifetime, discovery snapshots, persisted preferences, history, trust, diagnostics and transfers. It never opens sockets, implements a wire protocol, streams file bytes or weakens mutual certificate pinning. All potentially slow selection, persistence and filesystem work runs asynchronously. UI events marshal backend updates to the form thread.

## Workflows

- **Nearby devices:** online/offline state, locally paired state, search, refresh, send-to-selected and manual IPv4 entry. Discovery refreshes do not repeatedly rebuild an open recipient dropdown or discard the selected device. Manual entry requires the real peer installation GUID and does not create trust.
- **Send files:** native file picker, folder picker, drag/drop, bounded recursive preview, relative hierarchy, duplicate selection filtering, removal, clearing, total size, recipient selection and explicit sending. Expansion uses the existing backend selection validation. Links, unsafe names, conflicting paths and configured size/count limits remain enforced.
- **Pairing:** both installation IDs and independently verified SHA-256 fingerprints are exchanged. The dialog explains pairing on both PCs, exposes a copyable local public identity and saves only the fingerprint the user explicitly verifies. Unknown, changed and unpaired identities fail closed. Revocation blocks future handshakes and cancels that peer's active transfers.
- **Receiving:** modeless explicit approval shows the paired sender identity, file count, manifest, size and editable destination. Closing declines. The backend expires pending decisions; the corresponding window closes on a terminal transfer update or application shutdown. Destination creation and acceptance validation run outside the UI thread.
- **Activity:** current transfers plus up to 256 terminal summaries. Selection exposes progress, cancellation, destination opening and live details. Details include file count, total/handled bytes, percent, current file, average speed, ETA, status and actionable failure guidance. Previous-session history intentionally contains summary metadata without source paths or file names.
- **Settings:** device name, receive directory, TCP port (0 assigns a free port), discovery, notifications, tray behavior, startup and system/light/dark theme. Saving validates the destination, atomically persists preferences and recreates the application to apply immutable settings. Active transfers require an explicit cancel-and-apply choice. Startup registration changes only when the user edits that preference; a failed settings write rolls it back.
- **Tray and notifications:** restore, add files, settings and explicit exit. Optional close/minimize-to-tray keeps transfers running. Explicit exit drains/cancels the backend; closing the main window exits normally when tray behavior is disabled. Terminal transfer balloons honor the notification preference and open activity when clicked.
- **Diagnostics and errors:** diagnostics expose public identity, listening/discovery state, counts, certificate expiry and the rotating log directory. UI-thread exceptions log diagnostic details and initiate clean shutdown. Private certificate material is never copied or shown.

Keyboard shortcuts: `Ctrl+O` adds files, `Delete` removes the selected file, `F5` refreshes devices, `Ctrl+,` selects settings, and `Ctrl+Q` exits. Native tab navigation, accessible control names, per-monitor DPI scaling, table/flow layouts and a scrollable settings view are implemented. English static labels/buttons are backed by `Resources/Strings.resx`; dynamic messages remain English and no translated locale is claimed.

## Appearance and contrast

All UI remains exclusively Windows Forms. Light and dark palettes define paired colors for canvas, content, raised surfaces, inputs, selected rows, primary/hover/pressed/disabled buttons, secondary text, errors and success. Dark mode uses slate surfaces and a soft blue accent; light mode uses white content on a cool gray canvas. Text states exceed 5:1 contrast in both palettes, and input boundaries exceed 3:1. Windows high-contrast colors take precedence over the application preference.

Native WinForms subclasses explicitly paint tab strips, list headers/rows, dropdown items/arrows, buttons, checkboxes, progress tracks, input placeholders/borders and numeric spinner arrows. This avoids native light backgrounds being combined with custom light text. Keyboard, selection, accessibility and transfer behavior remain inherited from the original WinForms controls. The theme also covers tray menus and supported Windows title bars. OS-owned file pickers and message boxes retain Windows' own rendering.

Theme roles preserve muted, error and success colors through refreshes and repeated light/dark switching. Controls added after initial theme application inherit the active palette. Palette selection never depends on reading a control's previous background color.

## Verification

The portable suite covers the existing backend, desktop preferences and 47 palette contrast/hierarchy checks using the actual UI palette source. `Lantern.UiTests` runs a real STA Windows message loop and covers settings restart/theme persistence, pairing and sending a nested folder, and accepting/declining incoming transfers with destination choice. Native rendering regressions additionally exercise theme round trips, late-added controls, enabled/disabled buttons, dropdown/tab pixels, dialog fields and menus. Windows CI retains light/dark screenshots under the test-results artifact. The native UI suite is compiled on Linux and configured to execute on Windows CI. Do not report it as locally executed on Linux.

Before release, run Windows workflows at 100%, 125%, 150% and 200% DPI and across monitors. Check keyboard focus, screen-reader output, dark/system contrast, tray close/restore, notification policy, per-user startup registration, unexpected shutdown, physical two-PC pairing and LAN/firewall behavior. Execute installer/uninstaller and signing checks. These are runtime verification gates, not missing UI handlers.
